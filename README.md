# Wuwa-Map-Sync

WuWa Map Progress — расширение для настольного Firefox 140+, которое сохраняет
отметки «нашёл» на [карте WuWaBuild](https://www.wuwabuild.com/map) и синхронизирует
их через Google Drive. Написано на JavaScript, HTML и CSS без сборщика и зависимостей.

Ветка `dev` содержит исходники тестовой версии **1.1.1**. Это не подписанный релиз.
Поддержка Firefox для Android пока не заявлена.

## Возможности

- Локальная копия отметок обновляется каждые 2 секунды, пока открыт сайт.
- Двусторонняя синхронизация добавлений и снятия отметок примерно раз в минуту,
  пока запущен Firefox. После сна или при ограничениях фоновой работы задержка может быть больше.
- Локальные изменения сохраняются без интернета; неудачные отправки повторяются.
- Экспорт, импорт с добавлением или заменой и восстановление JSON.
- Одна предыдущая копия перед облачным изменением или импортом, доступная для скачивания.

Поступившие облачные изменения применяются к открытой карте с её перезагрузкой.
Если карта закрыта, они остаются в расширении до следующего открытия.

## Установка из исходников

1. Скачайте исходники ветки `dev` и распакуйте архив.
2. Создайте локальный `oauth-config.js`, скопировав `oauth-config.example.js`.
   Без заполненных полей локальное сохранение и JSON-функции работают,
   а подключение Google показывает сообщение об отсутствии настройки.
3. Откройте `about:debugging#/runtime/this-firefox` → «Загрузить временное дополнение»
   и выберите `manifest.json` в распакованной папке.
4. Обновите уже открытые вкладки карты.

Для обычной постоянной установки в Firefox Release нужен подписанный Mozilla XPI.
Временная установка предназначена для разработки и проверки.
[Подпись и распространение](https://extensionworkshop.com/documentation/publish/signing-and-distribution-overview/).

Перед обновлением экспортируйте текущие отметки в JSON. Для временного дополнения
обновите файлы в прежней папке и перезагрузите дополнение через `about:debugging`,
затем обновите вкладки карты. ID расширения сохранён с версии 1.0.1:
`wuwa-map-progress@wuwabuild.local`.

## Настройка Google для разработчика

В публичном репозитории находится шаблон OAuth-конфигурации. Реальный
`oauth-config.js` и скачанный Google JSON исключены из Git. Обычный пользователь
уже настроенной сборки только входит в Google и разрешает доступ.

Для собственной сборки создайте OAuth-клиент **Desktop app** в
[Google Cloud](https://console.cloud.google.com/), включите Google Drive API
и добавьте scope `https://www.googleapis.com/auth/drive.appdata`.
В локальном `oauth-config.js` заполните `clientId` значением `installed.client_id`,
а `clientSecret` — `installed.client_secret`, если Google его выдал.
Конфигурацию Web application с серверным секретом использовать нельзя.
При упаковке рабочей сборки локальный `oauth-config.js` должен быть включён в архив.

В режиме Testing добавьте аккаунт для входа в Audience → Test users.
Refresh token для такого режима обычно действует семь дней; для длительной работы
потребуется настроить Production и выполнить требования Google для приложения.
Для передачи отметок используйте один OAuth-проект и один Google-аккаунт на устройствах.

Вход использует Authorization Code + PKCE и проверку `state`. Пароли Google
расширение не получает. Настройки Desktop OAuth являются конфигурацией публичного
клиента: из настроенной сборки их можно извлечь. Скрытие конфигурации из Git
не заменяет защиту пользовательских токенов.
[Документация Google](https://developers.google.com/identity/protocols/oauth2/native-app).

## Данные и безопасность

Разрешение `drive.appdata` даёт доступ только к данным этого приложения в закрытой
`appDataFolder`. Файлы не отображаются в обычном интерфейсе Drive.
В облаке хранятся ID точек, признаки «поставлена/снята», счётчики изменений
и случайные ID устройств. Телеметрии нет.

Access token и refresh token сохраняются после входа в `browser.storage.local`
в профиле Firefox. Они не входят в исходники, JSON-экспорт или облачный прогресс.
Код расширения отдельно не шифрует это хранилище: доступ к файлам профиля Firefox
может раскрыть токены. Не публикуйте содержимое профиля или его локального хранилища.

«Отключить синхронизацию» удаляет локально сохранённые токены и останавливает обмен;
копии прогресса остаются. Разрешение в аккаунте Google не отзывается автоматически,
чтобы не отключать другие устройства. Его можно отозвать вручную в аккаунте Google.

## Проверка

Нужен Node.js с поддержкой встроенного test runner и Fetch API. Из корня репозитория:

```bash
node --test tests/sync.test.cjs
```

Тесты используют имитацию Firefox и Google API, не обращаются к настоящему Drive
и загружают пустой шаблон OAuth вместо реальной конфигурации. Проверяются объединение
двух устройств, снятие отметок, офлайн-правки, повтор отправки, перезапуск, импорт,
гонки при обновлении карты, повреждённые данные и проверки OAuth.

Реальный вход и первый обмен с Google Drive подтверждены пользователем для 1.1.1.
Передачу отметки между двумя независимыми профилями в обе стороны ещё нужно проверить вручную.

## Ограничения

Одновременные офлайн-правки одной точки разрешаются детерминированно по счётчику
изменений и ID устройства, а не по реальному времени. Независимые точки объединяются.
Снятие отметок сохраняется в истории синхронизации, чтобы старые копии их не возвращали.

Отсутствующий ключ отметок на сайте не считается удалением всех точек. Существующий
пустой список после ранее наблюдавшихся отметок считается снятием и синхронизируется.
Копия перед изменением хранится одна; для дополнительных резервных копий используйте JSON.

Не копируйте полный активный профиль Firefox на другое устройство: он получит тот же
ID устройства. Устанавливайте расширение в независимый профиль. Служебный ключ
`wuwa-map-progress-applied` в localStorage карты нужен для учёта применённых изменений.
